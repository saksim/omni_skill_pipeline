## What Changed

This internal release fixes the first real consumer-smoke failure found after
publishing `v0.2.0-internal.1`.

- Packaged `SKILL.template.md` and `skill.schema.json` into the Python wheel.
- Updated runtime settings so an installed wheel can fall back to packaged
  contracts when it is not running from a source checkout.
- Added a release consumer smoke script that verifies checksums, manifest
  contract, wheel installation, and `show-template` from the installed wheel.
- Wired the consumer smoke into the `Release` workflow before artifact upload and
  GitHub Release publication.
- Added tests for packaged contract resources and release consumer smoke failure
  modes.

## Why This Matters

`v0.2.0-internal.1` proved that GitHub Release publication worked, but a consumer
install exposed a gap: the wheel expected repository docs to exist beside the
installed package. That is not true for a normal user downloading a release.

This release closes that gap. A user can install the wheel outside the repository
and still run the template CLI smoke.

## How To Use It

Install the wheel from this release, then verify the CLI entry point:

```bash
python -m pip install omni_skill_pipeline-0.2.1-py3-none-any.whl
python -m omni_skill_pipeline.cli show-template
```

Verify downloaded files with:

```bash
sha256sum -c SHA256SUMS
```

Run the release consumer smoke against downloaded assets:

```bash
python scripts/release_consumer_smoke.py --release-dir . --expected-release-id v0.2.1-internal.1
```

## Release Boundary

This release improves the packaged artifact and post-release verification layer.
It still does not claim full production runtime deployment by itself. Docker,
Postgres, external beta, and real launch-gate evidence remain separate gates.
