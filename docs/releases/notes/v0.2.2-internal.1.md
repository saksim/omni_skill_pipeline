## 本次变化

本内部 release 关闭 API/CLI/review-queue 路径的非基础设施 dogfood 上线闭环。

- 修复 internal dogfood API smoke payload，使其使用当前 API schema contract 中的 `DistillGoal.audience`。
- 为 `scripts/internal_dogfood_smoke.py` 增加 JSON 和 Markdown 证据输出。
- 增加真实 HTTP dogfood smoke 证据，覆盖 `/healthz`、template retrieval、text distillation 和 pending review queue visibility。
- 让 FastAPI OpenAPI metadata 读取 package version，替代陈旧 hard-coded value。
- 刷新 broad launch readiness 和 internal dogfood readiness 证据。

## 为什么重要

`v0.2.1-internal.1` 让 release wheel 可安装。Docker/Postgres/K8s 之外的下一个上线阻塞点是 live internal API smoke 路径：smoke script 本身没有符合 API schema，输出也不足以作为持久 launch record。

本 release 让 internal dogfood API 路径可运行、可审计，但不声明 external Beta 或 GA readiness。

## 如何使用

对本地 API 执行 internal dogfood API smoke：

```bash
python scripts/internal_dogfood_smoke.py \
  --base-url http://127.0.0.1:8000 \
  --output docs/working/status/baselines/internal-dogfood-api-smoke-report.json \
  --summary-output docs/working/status/baselines/internal-dogfood-api-smoke-summary.md
```

以 consumer 视角验证 release wheel：

```bash
python scripts/release_consumer_smoke.py --release-dir . --expected-release-id v0.2.2-internal.1
```

## 发布边界

这是内部 dogfood launch release。它排除 Docker、Postgres、K8s、OCR hardening、encryption hardening 和 external real-loop collection。外部 launch gate 仍保持 `HOLD`，直到真实 launch-gate-eligible loops 达到文档阈值。
