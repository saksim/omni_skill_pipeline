# v0.2.6-internal.3 发布说明

## 本次变化

本内部版本把 2026-06-23 施工成果收束为一个可发布的自证闭环版本。它不把项目声明为外部 Beta、GA、SaaS 或生产 ready；它做的是让这些声明必须经过更严格、更可复盘的证据门禁。

相比 `v0.2.5-internal.2`，本版本新增和更新了以下内容：

- `distill -> export -> validate` 内部闭环现在可以按 review/lifecycle source of truth 正常推进；validator 仍保留 `REVIEW_APPROVAL_MISSING` 等保护逻辑，不靠删 gate 放行。
- release artifact 支持普通源码包 fallback：当 `git archive` 不可用时，`scripts/release_artifacts.py` 会创建 source-tree archive，并在 `release-manifest.json` 记录 `source_archive_mode=source_tree_fallback`。
- Python 支持口径从过宽声明收敛为 `>=3.11,<3.13`，并补齐 Python 3.11/3.12 的 CI evidence 合同、workflow artifact 聚合和 launch gate 可选硬门禁。
- 多模态质量门禁落地：`scripts/multimodal_quality_gate.py` 检查 text/audio/image/video 的质量评分、人审结论、OCR/ASR 降级和 critical issue。
- 真实 loop manifest preflight 纳入 strict launch gate：`scripts/launch_gate.py --require-real-loop-preflight` 会读取 GL-64 报告，拒绝 missing、invalid、pending 或 operator action 未清零的 real-loop manifest。
- agent smoke 真实性门禁加固：外部 readiness 不能把 `not_run` 或 failed 记录当作真实 agent 使用证据。
- 新增 Docker、Postgres、secrets、K8s、product surface 和 observability readiness 检查入口。它们提供生产化证据门禁，不把静态文档或 dry-run 伪装成生产 ready。
- CI、testing、script-name-map、operations、real-data intake、GitHub release workflow 和 06-23 施工蓝图归档已同步到当前手册层。

## 为什么重要

上一版本把真实数据接入方式写清楚了，但外部上线仍然容易被“能跑”和“可发布”混在一起。

本版本把边界切清楚：内部 dogfood 可以继续发布，外部 Beta/GA 必须等真实闭环证据通过。代码、文档和 launch gate 都按这个口径收紧。

## 如何使用

当前内部操作入口：

```text
docs/latest/operations/OPERATIONS.md
```

真实数据接入入口：

```text
docs/latest/operations/runbooks/real-data-intake-and-validation.md
```

Strict launch gate 示例：

```powershell
python scripts\launch_gate.py --require-ci-evidence --require-multimodal-quality-gate --require-real-loop-preflight --output - --summary-output - --max-evidence-age-hours 0 --print-json
```

## 发布边界

本版本仍不是外部 Beta、GA、SaaS 或生产部署声明。

仍不属于本版本完成范围：

- 10 个 launch-gate-eligible 真实闭环 manifest。
- text/audio/image/video 四类真实业务模态达标。
- 外部 Beta readiness。
- GA/SaaS readiness。
- 真实生产 Secret Manager/Vault/KMS 运行证据。
- 真实 Kubernetes 集群 rollout 证据。
- 真实 Docker/Postgres 长稳运行证据。
- 外部生产可观测 dashboard 证据。

## 验证

本版本发版前至少执行：

```powershell
python -m pytest -q
python scripts\doc_sync.py --output - --print-json
python scripts\launch_gate.py --require-real-loop-preflight --real-loop-preflight-report docs\working\status\baselines\real-trial-loop-collection\real-trial-loop-manifest-preflight-report.json --no-run-doc-sync --max-evidence-age-hours 0 --output - --summary-output - --print-json
```

预期口径：

- 全量测试应通过。
- `doc_sync.py` 应通过。
- 在没有真实 manifest 的 baseline 下，strict launch gate 可以继续返回 `HOLD`，并明确显示 real-loop preflight 或 real-loop coverage blocker。这会阻断外部上线声明，但不阻断内部 dogfood 发版。
