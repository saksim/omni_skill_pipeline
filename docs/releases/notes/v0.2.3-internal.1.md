## What Changed

This internal release adds local artifact encryption hardening for the
file-backed dogfood path.

- Added optional Fernet-based encrypted artifact envelopes for
  `FileArtifactRepository`.
- Added `OMNI_ARTIFACT_ENCRYPTION_MODE`, `OMNI_ARTIFACT_ENCRYPTION_KEY`, and
  `OMNI_ARTIFACT_ENCRYPTION_KEY_ID` settings.
- Kept default file persistence backward-compatible and plaintext unless
  encryption is explicitly enabled.
- Made encrypted review queue files readable by the configured repository so
  pending, consumed, and closed review workflows still operate.
- Added encryption tests for artifact confidentiality, review queue continuity,
  missing-key failure, config loading, and service factory wiring.

## Why This Matters

`v0.2.2-internal.1` completed the non-infrastructure internal dogfood API smoke
loop. The next non-Docker, non-Postgres, non-K8s launch gap was at-rest
protection for local generated artifacts.

This release closes that gap without introducing Vault, KMS, Kubernetes
secrets, or a database dependency. It remains an internal dogfood release, not
an external Beta or GA claim.

## How To Enable

Generate a Fernet key:

```bash
python -c "from omni_skill_pipeline.artifact_crypto import generate_fernet_key; print(generate_fernet_key())"
```

Enable encrypted file artifacts:

```bash
export OMNI_ARTIFACT_ENCRYPTION_MODE=fernet
export OMNI_ARTIFACT_ENCRYPTION_KEY="<generated-key>"
export OMNI_ARTIFACT_ENCRYPTION_KEY_ID="internal-dogfood-local"
```

On PowerShell:

```powershell
$env:OMNI_ARTIFACT_ENCRYPTION_MODE = "fernet"
$env:OMNI_ARTIFACT_ENCRYPTION_KEY = "<generated-key>"
$env:OMNI_ARTIFACT_ENCRYPTION_KEY_ID = "internal-dogfood-local"
```

## Release Boundary

This release covers local file artifact encryption hardening only. It still
excludes OCR hardening, Docker, Postgres, K8s, Vault/KMS integration, production
key rotation automation, and external real-loop collection. The external launch
gate remains `HOLD` until real launch-gate-eligible loops meet the documented
threshold.
