## 本次变化

本内部 release 为 file-backed dogfood 路径增加本地 artifact 加密加固。

- 为 `FileArtifactRepository` 增加可选 Fernet encrypted artifact envelopes。
- 增加 `OMNI_ARTIFACT_ENCRYPTION_MODE`、`OMNI_ARTIFACT_ENCRYPTION_KEY` 和 `OMNI_ARTIFACT_ENCRYPTION_KEY_ID` 配置。
- 保持默认 file persistence 向后兼容且为 plaintext；只有显式启用加密时才写入加密 envelope。
- 让 encrypted review queue files 可被已配置 repository 正常读取，使 pending、consumed 和 closed review workflows 继续可用。
- 增加加密测试，覆盖 artifact confidentiality、review queue continuity、missing-key failure、config loading 和 service factory wiring。

## 为什么重要

`v0.2.2-internal.1` 完成了非基础设施 internal dogfood API smoke loop。下一个非 Docker、非 Postgres、非 K8s 的上线缺口，是本地生成 artifact 的 at-rest protection。

本 release 在不引入 Vault、KMS、Kubernetes secrets 或数据库依赖的前提下关闭该缺口。它仍是内部 dogfood release，不是 external Beta 或 GA 声明。

## 如何启用

生成 Fernet key：

```bash
python -c "from omni_skill_pipeline.artifact_crypto import generate_fernet_key; print(generate_fernet_key())"
```

启用 encrypted file artifacts：

```bash
export OMNI_ARTIFACT_ENCRYPTION_MODE=fernet
export OMNI_ARTIFACT_ENCRYPTION_KEY="<generated-key>"
export OMNI_ARTIFACT_ENCRYPTION_KEY_ID="internal-dogfood-local"
```

PowerShell：

```powershell
$env:OMNI_ARTIFACT_ENCRYPTION_MODE = "fernet"
$env:OMNI_ARTIFACT_ENCRYPTION_KEY = "<generated-key>"
$env:OMNI_ARTIFACT_ENCRYPTION_KEY_ID = "internal-dogfood-local"
```

## 发布边界

本 release 只覆盖本地 file artifact encryption hardening。它仍排除 OCR hardening、Docker、Postgres、K8s、Vault/KMS integration、production key rotation automation 和 external real-loop collection。外部 launch gate 仍保持 `HOLD`，直到真实 launch-gate-eligible loops 达到文档阈值。
