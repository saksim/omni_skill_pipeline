## What Changed

This internal release turns the repository's green `main` branch into a repeatable
GitHub Release publication flow.

- Added a formal `Release` GitHub Actions workflow for `main` pushes, `v*` tags,
  and manual release dispatch.
- Added a release artifact pack with source archive, Python wheel, coverage XML,
  manifest, summary, and checksums.
- Added a dedicated release packaging script that validates release ids, filters
  distribution files, creates a source archive, and writes SHA256 checksums.
- Added workflow and artifact-pack tests so the release path is covered by CI.
- Added operator runbook documentation for tag-based publication, manual release,
  verification, and rollback.

## Why This Matters

Before this release, the project could pass CI but had no stable public handoff
point. Operators had to infer what to use from branch state and local artifacts.

After this release, a `v*` tag creates a GitHub Release with a reproducible pack
that can be downloaded, verified, and installed.

## How To Use It

Install the wheel from this release, then verify the CLI entry point:

```bash
python -m pip install omni_skill_pipeline-0.2.0-py3-none-any.whl
python -m omni_skill_pipeline.cli show-template
```

Verify downloaded files with:

```bash
sha256sum -c SHA256SUMS
```

For runtime/container validation, continue with:

```bash
bash scripts/linux_release.sh
```

## Release Boundary

This is an internal release mechanism milestone. It publishes a verified package
and source snapshot, but it does not claim full production deployment by itself.
The Docker/Postgres release switch remains the stricter runtime gate for full
production claims.

## Assets
