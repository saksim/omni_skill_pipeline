## 本次变化

本内部 release 将仓库绿色 `main` 分支转成可重复执行的 GitHub Release 发布流程。

- 增加正式的 `Release` GitHub Actions workflow，覆盖 `main` push、`v*` tag 和手动 release dispatch。
- 增加 release artifact pack，包含 source archive、Python wheel、coverage XML、manifest、summary 和 checksums。
- 增加专用 release packaging script，负责校验 release id、过滤 distribution files、创建 source archive 和写入 SHA256 checksums。
- 增加 workflow 和 artifact-pack 测试，让 release 路径纳入 CI 覆盖。
- 增加操作 runbook，覆盖基于 tag 的发布、手动发布、验证和回滚。

## 为什么重要

在本 release 之前，项目可以通过 CI，但没有稳定的公开交付点。操作人员只能从分支状态和本地产物推断应该使用什么。

本 release 之后，`v*` tag 会创建 GitHub Release，并生成可下载、可校验、可安装的可复现 artifact pack。

## 如何使用

安装本 release 的 wheel，然后验证 CLI 入口：

```bash
python -m pip install omni_skill_pipeline-0.2.0-py3-none-any.whl
python -m omni_skill_pipeline.cli show-template
```

验证下载文件：

```bash
sha256sum -c SHA256SUMS
```

运行时或容器验证继续使用：

```bash
bash scripts/linux_release.sh
```

## 发布边界

这是内部 release 机制里程碑。它发布经过验证的 package 和 source snapshot，但不单独声明完整生产部署。Docker/Postgres release switch 仍是完整生产声明的更严格运行时门禁。

## 产物

- `omni-skill-pipeline-source-v0.2.0-internal.1.tar.gz`：tag 对应的 source snapshot。
- `omni_skill_pipeline-0.2.0-py3-none-any.whl`：可安装 Python package。
- `release-manifest.json`：机器可读 release metadata。
- `release-summary.md`：生成的 release summary。
- `SHA256SUMS`：下载产物 checksum 文件。
- `coverage.xml`：release workflow 生成的 coverage report。
